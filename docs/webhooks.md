# Meadow webhooks

Configure one workspace endpoint in **Agents & API keys → Webhooks**. The URL must use public HTTPS on port 443. Save, test, remove, and secret rotation require a signed-in Meadow session; API keys cannot change the destination or read its secret. The server uses its existing `BRIDGE_ENCRYPTION_KEY` to encrypt webhook signing secrets at rest.

The full signing secret appears only when creating a destination, changing its URL, or rotating the secret. Save it on your receiver. Changing the destination, removing it, or rotating the secret removes pending deliveries. Local preview allows configuration but disables outbound delivery.

## Events

Each event has `id`, `type`, `created_at` (ISO 8601), and `data`.

- `post.completed`: one event per destination outcome, with `project_id`, `post_id`, `delivery_id`, `account_id`, `platform`, `status`, `external_ref`, and `url`. Status is `published`, `failed`, `needs_review`, or `awaiting_publish`. The last status means a TikTok inbox upload requires the user to finish publication in TikTok. A manually retried delivery may produce another completion event. Waiting for reconnection or retrying automatically is not a completion.
- `connection.needs_reconnect`: emitted when a connected account changes to `reconnect_required`, with `project_id`, `account_id`, and `platform`. Repeated errors on that same disconnected authorization do not emit another event.
- `webhook.test`: generated by **Send test** with a message in `data`.

Events contain references and outcomes, without account credentials, post content, or media. Events are queued with the outcome in the same database transaction. Connection erasure removes that account’s queued events. Deletion of the workspace removes the configuration and outbox; no delivery starts while workspace deletion is pending.

## Verify signatures

`X-Meadow-Signature` contains `t=TIMESTAMP,v1=HEX_SIGNATURE`. Compute HMAC-SHA256 over `${timestamp}.${rawBody}` using the signing secret. Use the exact raw request bytes before JSON parsing, check the timestamp within five minutes, and compare signatures in constant time.

```js
import { createHmac, timingSafeEqual } from "node:crypto";

export function verifyMeadowWebhook(rawBody, signature, secret) {
  const match = /^t=(\d+),v1=([a-f0-9]{64})$/.exec(signature || "");
  if (!match || Math.abs(Date.now() / 1000 - Number(match[1])) > 300) return false;
  const expected = createHmac("sha256", secret)
    .update(`${match[1]}.`).update(rawBody).digest();
  return timingSafeEqual(expected, Buffer.from(match[2], "hex"));
}
```

Return a 2xx response within ten seconds. Redirects are not followed. DNS is checked on each attempt and the validated public address is pinned to the HTTPS request to prevent DNS rebinding. Private, loopback, link-local, and reserved destinations are rejected.

Failed deliveries retry after one, two, four, and eight minutes (five total attempts). A crash or lost response can cause a duplicate. Deduplicate by the JSON event `id` or `X-Meadow-Event-Id`; signatures use a fresh timestamp on each attempt. Event ordering is not guaranteed. The UI shows the most recent attempt; event records expire after seven days.

## Settings API

All endpoints below require session authentication and use `/api/bridge`:

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/webhooks` | Read URL, readiness, and last delivery (never the secret) |
| POST | `/webhooks` | Save `{ "url": "https://your-server.com/webhook" }` |
| DELETE | `/webhooks` | Remove destination and pending events |
| POST | `/webhooks/rotate-secret` | Generate a new signing secret |
| POST | `/webhooks/test` | Send a signed test and return the delivery status |

Save and rotation return `secret` only when a new secret is generated.
